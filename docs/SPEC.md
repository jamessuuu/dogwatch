## 1. Goal + non-goals

**Goal.** A real scheduled autonomous pipeline whose published audit trail *is* the product. Every
night dogwatch checks the public surfaces James operates, then publishes one immutable record: what
it checked, what it found (every finding citing recorded evidence), what it did, what it refused,
what a human gated, and what it cost to the micro-dollar — including an explicit
absence-of-evidence section on the many nights it finds nothing. Human gates on every action that
leaves the dogwatch repo. Effects, gates and audit come from `@jamessuuu/sluice` in production;
dogwatch is that library's first real consumer.

**Non-goals (hard guards — refusals, not backlog).**
1. **No third-party surfaces.** dogwatch watches only what James operates. It never publishes a
   claim about anyone else's software. (Kills the vendor-liability and manufactured-finding risk at
   the root.)
2. **No content generation.** No posts, digests, newsletters, "insights". The only model-authored
   text is one labelled advisory paragraph per eventful run and one human-approved issue draft.
   *A run with nothing to say publishes that it has nothing to say, with the checks it ran.*
3. **No sibling reimplementation.** Model drift is tiltmeter's; MCP contract drift is snapgauge's.
   dogwatch **consumes their published artifacts** (freshness + schema validity) and re-derives none
   of their logic.
4. **No sluice reimplementation.** No bespoke retry, breaker, idempotency, gate or audit code — if
   dogwatch needs one, it calls sluice or files against sluice.
5. **No npm package, no installable product.** This is an operated instance (§4).
6. **No uptime SLA, no paging, no synthetic performance scores.** One request, one runner, one
   region, once a night. Timings are metrics, never findings.
7. **No secret in any published artifact**, ever.

## 2. The job (the decision the spec had to make)

**Decided: the night watch over the six public surfaces of this program** — the five showcase sites
(tiltmeter, chaff, sluice, snapgauge, dogwatch) plus agentjames.vercel.app, their repos, their
scheduled workflows, and their published npm artifacts.

| Candidate | Verdict |
|---|---|
| **(i) Watch the program's own public surfaces** | **CHOSEN.** Public inputs → public outputs: every check publishes the exact request and a `curl` line, so a visitor reproduces it in one command. The job is load-bearing, not decorative — D3 blackouts, the D4 **60-day scheduled-workflow auto-disable**, a silently dropped security header, a broken backlink, an unpublishable package are the exact ways this program rots while James is elsewhere. Deterministic, ~$0, and genuinely quiet most nights. Because the surfaces are James's own, publishing a finding makes no claim about a third party — the honesty guard is structural, not editorial. |
| (ii) Watch the MCP-spec / agent-ecosystem landscape | **REJECTED.** Findings would be summaries of other people's changelogs — a scheduled content bot in a trench coat, exactly the P5 death condition. It overlaps snapgauge's board, requires scraping third-party prose (LLM extraction ⇒ unverifiable findings), and its "nothing happened" nights are indistinguishable from "we failed to notice". |
| (iii) Anything watching third-party infrastructure | **REJECTED.** Unverifiable by a visitor, liability-shaped, and it makes the quiet-night property dishonest. |

**Editorial rule (binding).** A finding is a statement about *one request dogwatch made*
("`GET https://… → 503 at 2026-08-09T15:02:11Z`"), never about a vendor's state ("npm is down").
Finding text is **generated by the rule's template from recorded evidence** and CI re-derives it
(§7 R13), so a model or a human cannot author a finding at all.

**Check families (v1, ~50–60 checks declared in `targets.json`, not in code).**

| Family | Asserts | Representative rule ids |
|---|---|---|
| `reach` | `/` reachable, final URL and redirect chain unchanged | `reach.status_not_200`, `reach.redirect_chain_changed` |
| `header` | declared security/policy headers present; value drift vs the previous record | `header.missing`, `header.value_changed` |
| `brand` | BRAND-KIT/D1 compliance **in production**: footer attribution + backlink to agentjames on every crawled page, chip-mark favicon reachable | `brand.backlink_missing`, `brand.favicon_missing` |
| `link` | same-origin crawl ≤30 pages/site; external links HEAD-checked (≤60/site, 7-day result cache from the previous record) | `link.broken`, `link.offsite_redirect` |
| `weight` | transfer bytes of `/` vs a declared budget (deterministic). Timings recorded as metrics only | `weight.budget_exceeded` |
| `artifact` | sibling published artifacts exist, parse against their **own published schema**, and are within their declared cadence (dead-man) | `artifact.unreachable`, `artifact.schema_invalid`, `artifact.stale` |
| `repo` | scheduled workflows still `active` (the 60-day rule), last success within cadence+slack, default branch CI green | `repo.schedule_disabled`, `repo.schedule_overdue`, `repo.default_branch_red` |
| `pkg` | registry metadata; `npm i <pkg>@latest` + smoke command in a clean temp dir; published version matches the repo tag; deprecation/unexpected-publish | `pkg.install_failed`, `pkg.version_tag_mismatch`, `pkg.unexpected_publish`, `pkg.deprecated` |
| `watch` | dogwatch on itself: schedule lateness, gap since previous run, audit-chain continuity, store mode | `watch.run_missed`, `watch.chain_gap`, `watch.late` |

Download counts and star counts are **metrics**: recorded, never judged, never renderable as findings
(§7 R14). A number moving is not an event.

**Hysteresis.** A `medium` finding must be observed in **2 consecutive runs** before any action is
proposed; `high` acts on first sight. Night one publishes it as `status: "unconfirmed"`. This is why
dogwatch does not manufacture urgency.

## 3. Data model

**Decision 1 — the product's state is the committed artifact, not a database.** Baselines
(previous headers, redirect chains, external-link cache, npm versions, chain head) are read from the
**previous published run record in git**. The git history *is* the time series: publicly verifiable,
diffable, survives every platform going dark, and doubles as the D4 keep-alive commit. Neon holds
only what must be durable *across processes*: sluice's four tables plus one counter table.

**Run record** — `runs/<YYYY>/<YYYY-MM-DD>-<runId>.json`, canonical JSON (keys sorted, 2-space,
`\n`, trailing newline). Schema published at `schemas/run-record.v1.json`.

```jsonc
{ formatVersion: 1, runId, kind: "scheduled"|"manual"|"gap",
  watchVersion, checkPackVersion, commit, targetsHash, pricingManifest,
  scheduledFor, startedAt, endedAt, trigger: { workflow, runUrl, actor },
  checks:  [ { id, family, targetId, ruleId, title,
               request: { method, url, headersSent[], timeoutMs },
               observedAt, verdict: "pass"|"finding"|"error"|"skipped",
               skipReason?, errorCode?,
               evidence: { status?, finalUrl?, redirects[], headers{allowlisted}, bodySha256?,
                           bytes?, ms?, tlsNotAfter?, json? },
               reproduce: "curl -sSI https://…" } ],          // MUST be non-empty
  findings: [ { id: "F-…", checkId, ruleId, severity, status: "unconfirmed"|"confirmed",
                statement,                                     // template(evidence) — CI re-derives
                sources: [ { url, method, status, retrievedAt, evidencePath } ],   // ≥1 REQUIRED
                firstSeenRunId, fingerprint,
                advisory?: { severity, note, model, agreesWithRule } } ],
  absenceOfEvidence: { statement, checksClean, byFamily{}, notChecked:[{checkId, reasonCode}] },
  metrics: [ { id, targetId, name, value, unit, delta?, note: "recorded, not judged" } ],
  actions: [ { id, kind: "issue.open"|"issue.comment", target, status:"proposed"|"gated_pending"
               |"executed"|"refused", gateId?, effectKey?, effectOutcome?, artifactUrl?,
               draft?: { title, body, author:"claude-haiku-4-5", approvedBy?, approvedAt? } } ],
  gates:  [ { id, key, status, openedAt, expiresAt, decidedAt?, decidedBy?, decisionChannel?, reason? } ],
  refusals: [ { subject, reasonCode, detail } ],
  cost:   { currency:"USD", microUsd, certainty:"reported"|"unknown", breakdown:{…}, method },
  llm:    { calls, model?, inputTokens, outputTokens, microUsd, rejected?[], reason? },
  degraded: [ { component, reason } ],
  audit:  { namespace:"dogwatch", store:"postgres"|"memory", fromSeq, toSeq, prevHead, head,
            verified: bool, events:[…] },
  chain:  { prevRunId, prevRecordHash, recordHash },
  amendments: [ { at, by, kind, events[], actions[], refusals[], amendmentHash } ] }
```

**Decision 2 — two chains, one immutable base.** `chain.recordHash = sha256(canonicalJson(record
minus amendments))`; the next run's `prevRecordHash` points at that stable base, so a retro-edit to
any published record breaks every later record *and* shows in the public git history.
Post-publication facts (a gate decided 14 hours later) land in `amendments[]`, each hash-linked to
the previous amendment. Nothing published is ever rewritten. `audit.fromSeq = previous record's
toSeq + 1`; a discontinuity publishes `watch.chain_gap` rather than being silently closed.

**Decision 3 — a missed run is a published artifact.** If the schedule slips a night, the next run
emits a `kind:"gap"` record (`expectedAt`, `detectedAt`, the Actions run URL and conclusion) before
its own. Silence is never allowed to look like health.

**`targets.json`** (config, no executable code — the site parses it) declares `sites[]`, `repos[]`,
`packages[]`, `artifacts[]` and `actionPolicy` (`issueRepos[]`, `confirmations: 2`,
`gateTimeoutHours: 48`). Its sha256 is stamped into every record; a change to it is visible in the
diff of the next run.

**Neon** (D5, one project) — sluice's `sluice_effect | sluice_gate | sluice_event | sluice_circuit`
via `@jamessuuu/sluice-store-postgres` (its migrations, not ours), plus exactly one dogwatch table:
`dogwatch_budget(day date PK, llm_calls, input_tokens, output_tokens, micro_usd, decide_attempts)` —
the D2 app-level counter, checked **before** any model call and incremented on every decide attempt.
Forward-only additive migrations, checked in, `db:migrate` + `db:seed`.

**Retention.** Records are never deleted. ~80 KB/night ≈ 29 MB/year in git; any record > 512 KB
truncates evidence bodies with `truncated:true` markers (a truncated check may not produce a `high`
finding). Monthly rollups are §14 Q5, not v1.

## 4. Module / boundary map · repo layout · what ships

```
dogwatch/                          GitHub jamessuuu/dogwatch (public, MIT + brand carve-out)
  packages/dogwatch/    PRIVATE, never published — bin `dogwatch`
    src/checks/   one module per family: pure rule(evidence) → finding|pass  (isomorphic, zero I/O)
    src/probe/    http | tls | github | npm | crawl   ← the ONLY I/O; injected as a Probe interface
    src/record/   builder · canonical JSON · hashing · index · renderer
    src/verify/   rubric validator + rule re-derivation (pure, runs in Node AND the browser)
    src/effects/  sluice wiring: run() · gates · audit export · action executors · notifiers
    src/llm/      advisory summarizer + issue drafter (the only file importing @anthropic-ai/sdk)
    src/cli/      watch | resume | verify | render | gate  (only place with env / process.exit)
  apps/web/       Next.js 16.3 — static pages + ONE route handler (/api/gate/decide)
  runs/<YYYY>/*.json · runs/index.json · state/pending-gates.json      the product
  targets.json · pricing.2026-08-08.json · schemas/{run-record.v1,foreign/*}.json
  fixtures/{transcripts,records,violations}/ · docs/{SPEC,OPERATIONS,SECURITY}.md · scripts/brand.mjs
  .github/workflows/{watch.yml,resume.yml,ci.yml,canary.yml}
```

**What ships to npm: nothing, and the README says so in one line.** The value here is an *operated
record*, not code someone installs; publishing would imply support for other people's surfaces that
a 2h/week operator will not provide, and the check pack is tuned to six surfaces James controls.
The repo is public and fork-and-operate is documented in OPERATIONS.md as **unsupported**.

**Isolation rules.** `src/checks` and `src/verify` never import `node:*` (that is what lets the
browser re-verify a published record). `src/probe` is the only network code and is injected, so the
whole pipeline replays offline from recorded transcripts (§11). `src/llm` is imported by exactly one
call site and cannot construct a `Finding` — the type does not permit it. The notification composer
for public artifacts takes a `PublicGateSummary` that **has no token field**, so an approval token
cannot reach a public issue by construction.

## 5. Run architecture

**Executor: GitHub Actions. Vercel Workflows is not used.** Justification, in order of weight:
1. **The dogfood is the point.** If Workflows carried the gate, dogwatch would prove Vercel's
   human-in-the-loop primitive, not sluice's — collapsing P5's structural role (SELECTION.md).
2. **D4 is binding** for scheduling; Hobby cron is 1/day ±59 min.
3. Hobby Workflows retains run data **1 day** (feasibility §1.7) — it is not an audit trail, so we
   persist our own regardless; the second engine would buy nothing and cost a dependency.
4. The run needs full outbound HTTP, a TLS socket, `npm i` in a temp dir and a git commit — a
   runner, not a 300s function.
5. Actions on a public repo is free and unmetered, and the run's own commit is the D4 keep-alive.
6. sluice's own decided doctrine: *"waits > 5 minutes must use `open()` + return, and resume from a
   scheduled poller (`claimDecided`, GitHub Actions every 5 min per D4)."* We are following the
   library's documented shape, not inventing one.

**Workflows.**

| File | Schedule | Does |
|---|---|---|
| `watch.yml` | `0 15 * * *` (≈01:00 AEST) + `workflow_dispatch` | probe → derive findings → advisory (capped) → propose actions → open gates → publish record + index + `state/pending-gates.json` → commit → push (deploy) |
| `resume.yml` | `*/30 * * * *` + `workflow_dispatch{gateId,decision,reason}` | **reads `state/pending-gates.json` first and exits in ~5s touching nothing when it is empty**; otherwise `gates.sweepTimeouts()` → `gates.claimDecided()` → execute approved actions through `sluice.run()` → append amendment → commit |
| `ci.yml` | push/PR | five stages (§11) |
| `canary.yml` | weekly | runs the eval against sluice `main` instead of the pinned version; a break proposes an issue **on sluice** through the normal gate (the consumer-contract canary) |

**Neon wiring.** `createSluice({ store: postgresStore(DATABASE_URL), namespace: 'dogwatch',
owner: 'gha:'+run_id, approvalSecret: APPROVAL_SECRET, audit: { chain: true } })`. Every probe runs
inside `sluice.run({ key: 'probe:'+runId+':'+checkId, circuitKey: host, retentionMs: 24h })` — so
retries, the per-host breaker and the audit events are sluice's, per the consumer contract ("`run()`
per tool call"), and a host that is failing hard produces `skipped: circuit_open` instead of ten
timeouts. Outward effects use **intent-derived** keys:
`idempotencyKey({ tool:'github.issue.open', repo, ruleId, targetId, fingerprint })` with
`retentionMs: 90d` — the same recurring finding never files a second issue, on night 2 or night 40.
**The poller reads git before it reads Postgres**, which is what keeps the nightly cost inside Neon
Free's 100 CU-hours (quiet nights: one wake; gate nights: bounded polling, math in OPERATIONS.md).

**Gate flow, end to end.**
1. A confirmed finding whose target maps to `actionPolicy.issueRepos` produces
   `action{status:'proposed'}` + a Haiku-drafted issue title/body (§8).
2. `sluice.gates.open({ key: fingerprint, action, presentation, requester, timeoutMs: 48h,
   onTimeout: 'reject', resumeContext: { runId, recordPath, actionId, effectKey } })` — idempotent
   on the key, so a re-run never opens a second gate.
3. **Notification, two channels.** Always: an issue in **dogwatch's own repo** (a self-repo write,
   ungated) carrying the gate id, the rendered action and a link to `/gate?id=…` — **no token**.
   Optionally (recommended, and what exercises sluice's token path in production): a POST to
   `NOTIFY_WEBHOOK_URL` carrying the tokenized link from `gates.mintToken(id,{ttlMs:48h})`.
4. **Decision, three channels, all writing through `sluice.gates.decide` and all recorded with
   `decisionChannel`:** (a) `POST /api/gate/decide` with the single-use HMAC token; (b)
   `workflow_dispatch` on `resume.yml` — authenticated by GitHub repo permissions, works with no
   token and no Vercel, usable from the GitHub mobile app; (c) `dogwatch gate decide` locally
   (break-glass, recorded as such).
5. `resume.yml` claims the decision (leased), executes through `sluice.run()` (exactly-once across
   duplicate pollers and crashes), appends an amendment with the sluice events and the artifact URL,
   closes the dogwatch gate issue with the outcome, and clears `state/pending-gates.json`.
6. **Timeout = fail closed.** 48h with no decision ⇒ `timed_out` ⇒ `onTimeout:'reject'` ⇒ amendment
   publishes `refusal{ reasonCode:'gate_timed_out' }`. No action, no escalation, no retry.

**Autonomy ladder (published in the README).** L2 *auto*: everything inside the dogwatch repo —
publishing the record, committing artifacts, opening/closing dogwatch's own gate issues. L3 *human
gate*: every write to a repo dogwatch does not own. **Nothing** dogwatch can do touches a system
James does not operate. Publishing the record is deliberately ungated, with the reason stated:
withholding a run behind an approval would make the watch only as live as James's inbox and would
defeat the one promise the product makes.

## 6. API surface

**CLI** (`dogwatch`, private bin).

| Command | Does |
|---|---|
| `dogwatch watch [--dry-run] [--only <family>] [--targets f]` | the full run. `--dry-run` = no store writes, no commit, no gates, prints the record |
| `dogwatch resume` | sweep timeouts → claim decided → execute → amend |
| `dogwatch verify <record… \|--all> [--rerun-rules] [--offline]` | rubric validator + rule re-derivation + chain verification. Exit codes below |
| `dogwatch render` | regenerate `runs/index.json` + `state/pending-gates.json` (CI drift-checks the output) |
| `dogwatch gate ls\|show\|decide` | operator break-glass |

Exit codes: `0` clean · `1` findings at/above the gate · `2` probe/environment failure · `3` rubric
violation in a record · `4` usage/config error · `5` internal. 1 vs 3 is deliberate: different owner.

**HTTP (`apps/web`).**

| Route | Auth | Notes |
|---|---|---|
| `GET /` `/runs` `/runs/<id>` `/checks` `/gates` `/methodology` `/gate` | none | fully static, built from committed JSON; render with every function paused (D3) |
| `POST /api/gate/decide` | **single-use HMAC token (sluice `mintToken`)** | the only write path in the entire product. Zod-parsed body `{gateId, decision, token, reason?}`; timing-safe verify; nonce burned by the same conditional update that records the decision |

**The one Hobby WAF rate-limit rule binds to `/api/gate/decide`** (5 req/min per IP) plus an
app-level counter (`dogwatch_budget.decide_attempts`, 200/day → 429). The model path is not reachable
from the web at all, which is why the WAF rule is spent here — stated in the README with the reason.

**sluice consumption (the frozen surface, and nothing else).** `createSluice`, `idempotencyKey`,
`sluice.run`, `sluice.gates.{open,decide,claimDecided,mintToken,sweepTimeouts,get}`,
`sluice.audit.{append,export,verify}`, `MemoryStore` in tests and the browser verifier,
`@jamessuuu/sluice-store-postgres` in production. Pinned exact; `canary.yml` tracks `main`.

## 7. The honesty rubric as a CI-checkable schema

`dogwatch verify` runs on **every committed record on every push** (cheap, deterministic, offline).
Each rule has an error code; §11 plants one violation per rule and asserts the exact code.

| # | Rule | Code |
|---|---|---|
| R1 | `checks[]` non-empty and every check has a terminal verdict | `E_NO_CHECKS`, `E_CHECK_NONTERMINAL` |
| R2 | every finding references a check whose verdict is `finding` | `E_ORPHAN_FINDING` |
| R3 | every `finding`-verdict check is referenced by ≥1 finding | `E_UNREPORTED_CHECK` |
| R4 | **every finding carries ≥1 source: absolute https URL + ISO-8601 `retrievedAt` inside `[startedAt,endedAt]` + an `evidencePath` that resolves inside this record** | `E_UNSOURCED_FINDING` |
| R5 | **`findings` empty ⇒ `absenceOfEvidence` populated** and `checksClean == count(pass)`; the statement is required in every run, empty or not | `E_NO_ABSENCE_SECTION` |
| R6 | `skipped` and `error` require a machine reason code from the enum and appear in `notChecked`; neither may be counted clean | `E_SILENT_SKIP` |
| R7 | every action has a legal status; `executed` requires an approved `gateId` + `effectKey` + `effectOutcome`; `refused` requires a `reasonCode` | `E_ACTION_UNBACKED` |
| R8 | every gate resolves to a `gate.opened` + terminal audit event pair, or is `pending` with `expiresAt` in the future | `E_GATE_UNBACKED` |
| R9 | `cost.microUsd` equals the sum of its breakdown; `llm.calls > 0` ⇒ provider-reported usage tokens > 0; usage missing ⇒ `certainty:"unknown"` | `E_COST_UNBACKED` |
| R10 | advisory fields absent when `llm.calls == 0`; advisory text references only existing finding ids and contains **no URL outside the record's evidence URL set** | `E_ADVISORY_UNGROUNDED` |
| R11 | `audit.events` non-empty, `seq` contiguous, chain verifies, `fromSeq == prevRecord.toSeq + 1` or a `watch.chain_gap` finding exists | `E_CHAIN_BROKEN` |
| R12 | `chain.recordHash` matches the canonical hash of the base record; `prevRecordHash` matches the previous run | `E_RECORD_TAMPERED` |
| R13 | **every `finding.statement` is byte-identical to `template(ruleId, evidence)` re-derived offline, and the whole finding set is exactly reproduced by re-running the rules over stored evidence** (`--rerun-rules`) | `E_MANUFACTURED_FINDING` |
| R14 | no metric carries a severity or appears in `findings` | `E_METRIC_AS_FINDING` |
| R15 | no value in the record matches the secret-shape denylist; header capture is allowlist-only | `E_SECRET_LEAK` |

**R13 is the anti-manufacture guarantee** and the reason a model can never create a finding:
findings are a pure function of recorded evidence, the evidence ships inside the published record,
and anyone — including a visitor's browser — can re-derive them.

**Tamper-evidence.** `audit.verified` is `sluice.audit.verify()` at publish time (DB side). Offline
and in the browser, the verifier seeds a sluice `MemoryStore` with the record's exported events and
calls the same `audit.verify()` — sluice's primitive, not a copy of it (§14 Q1). Independently, the
cross-run `recordHash` chain plus the public git history make a silent retro-edit detectable by a
stranger with `git log -p` and one command.

## 8. LLM usage + cost safety (D2)

**Where a model is used: two calls, both advisory, neither able to gate anything.**

| Step | When | Shape |
|---|---|---|
| `triage` | only when `findings.length > 0` | Haiku 4.5, **forced tool schema** `{advisorySeverity: enum, note: ≤600 chars, referencedFindingIds: string[], proposedAction: "none"\|"open_issue"\|"watch"}`, `max_tokens` 800. Zod-validated; ids must be a subset of real ids; URLs must be in the evidence set. `proposedAction` is **displayed and ignored** — the deterministic rule table decides whether a gate opens, and when advisory severity disagrees with the rule severity the record publishes both plus `agreesWithRule:false` (the published disagreement rate is a real artifact) |
| `draft` | only when a gate will open | drafts the issue title/body a human then approves verbatim. Public text authored by a model carries an attribution line and a link to the run record |

**No model call on a quiet night** — `llm:{calls:0, reason:"no_findings"}`. Quiet nights cost
exactly $0.000000, which is a property worth publishing.

**Injection guard.** The model never sees page bodies — only structured evidence (status codes,
allowlisted header values truncated to 200 chars, URLs, counts, rule ids), delimited as untrusted
data and never concatenated into the instruction region. The URL-allowlist validator catches any
fabricated link.

**Caps and the degrade path.** ≤2 calls/run; ≤4,000 input and ≤800 output tokens per call; daily
ceiling **20 calls / 100k input / 20k output / $0.20** in `dogwatch_budget`, checked **before** each
call. Trip, API error, schema-invalid output or a caller-side timeout ⇒ the deterministic summary
(which is always computed anyway) stands alone and the record publishes
`degraded:[{component:"llm", reason:"daily_cap"|"api_error"|"schema_reject"|"indeterminate"}]`.
Prompt caching is deliberately **not** used and the reason is stated: at ~3k unique tokens used once,
the 1.25× write multiplier costs more than the 0.1× read saves.

**Abuse-case numbers (§7.8).** Expected: ~$0.011 per eventful run, ≤6 eventful runs/month ≈
**$0.07/month**. Worst case: **$0.20/day = $6.20/month**, clamped by the Neon counter — and there is
no public path that triggers a model call at all (runs come from the schedule or from a
`workflow_dispatch` only the repo owner can fire, with a concurrency group preventing overlap).
Non-token costs are asserted **"$0.00 billed, not $0.00 consumed"**: Actions seconds, Neon
statements and function invocations are recorded as consumed quantities with the free-tier reason.
Every price comes from `pricing.<date>.json`, never a constant.

**Cost is reported in integer micro-USD** and rendered at four decimals. Rounding a $0.0055 run to
"$0.01" would overstate it by 2×; the README says so, because the director's rubric scores cost
accuracy.

## 9. Failure contracts (the ugly paths)

| Situation | Contract |
|---|---|
| Neon suspended / over quota | Run degrades to `MemoryStore`: probes and findings still valid (pure functions of evidence), record publishes `audit.store:"memory"`, `chain.anchored:false`, and **no gate can open** ⇒ every proposed action is `refused{reasonCode:"store_unavailable"}`. Fail closed, never fail silent |
| Runner killed mid-run (job timeout 12 min) | Nothing is published; the *next* run emits a `kind:"gap"` record citing the failed Actions run URL. A missing night is an artifact |
| Duplicate/overlapping runs | Concurrency group `dogwatch-watch`; two records are legal (different runs), duplicate *effects* are not — intent-derived keys make the second one a `replayed` no-op |
| Recurring finding, 40 nights | One issue, ever: effect key = finding fingerprint, `retentionMs: 90d`. Nights 2–40 publish `refusal{reasonCode:"duplicate_suppressed", priorRunId}` |
| GitHub API fails mid-issue-create | sluice classifies. `failed` ⇒ retryable, published. **`indeterminate` ⇒ `onIndeterminate:'fail'`** ⇒ published verbatim ("we do not know whether the issue was created; not retried"), and the next run **reconciles** by searching the repo for the hidden marker `<!-- dogwatch:effect:<key> -->` and publishes the resolution |
| Gate approved twice / approve-reject race | sluice F6: first writer wins, the second returns the recorded decision. Both attempts appear in the audit trail |
| Approval token stolen or replayed | Single-use nonce burned by the deciding update, 48h expiry, timing-safe compare, `E_BAD_TOKEN` otherwise. The token never appears in a public artifact (type-enforced). Decision channel + IP hash are recorded |
| Gate never decided | 48h ⇒ `timed_out` ⇒ **reject** (fail closed) ⇒ published refusal. No auto-approve exists anywhere |
| Vercel blackout (D3) | Every page is static and keeps rendering; only `/api/gate/decide` is gone, so decisions route through `workflow_dispatch` or the CLI. The record JSON in git is canonical and the README says so |
| GitHub/npm API 403 rate-limited | check verdict `error` with the code, listed in `notChecked`. **Never** counted as `pass` |
| A sibling artifact 404s (not built yet) | `skipped{reasonCode:"not_published"}` with the reason printed — an unbuilt sibling is not a finding |
| Flapping check | 2-consecutive-run confirmation before action; night one publishes `status:"unconfirmed"` |
| Record > 512 KB | evidence bodies truncated with `truncated:true`; a truncated check cannot produce a `high` finding |
| dogwatch finds a fault in dogwatch | files in its own repo, ungated (L2). Documented, not an exception |
| Runner killed AFTER `resume`'s `claim.ack()` but BEFORE `resume.yml`'s commit+push step ever runs (or that push is rejected and exhausts its retries) | **Documented residual window, not yet closed.** `effects/resume.ts` writes the amended record to disk and calls `claim.ack()` inside the SAME process, in that order — but `resume.yml`'s `git commit && git push` is a separate, later workflow step. sluice's exactly-once guarantee covers the EFFECT (the GitHub issue is never opened twice); it says nothing about whether the record documenting that decision ever reaches git. Once `ack()` succeeds, `claimDecided` will never return that gate again — there is no automatic second chance. `resume.yml`'s push retries with a rebase against exactly this race (a concurrent `watch.yml`/`resume.yml` push landing first), but a runner killed between the two steps, or a rebase that hits a genuine conflict rather than a race, still loses the amendment. `effects/scenarios.test.ts`'s crash-after-ack scenario pins this behavior; `docs/OPERATIONS.md` names the operational recovery |

## 10. The site (`apps/web`)

Next.js 16.3 / React 19.2 / TS strict + `noUncheckedIndexedAccess` / Tailwind 4. All pages
prerendered from committed JSON; one route handler total (§6).

- **`/`** — what the watch is, the last run in one line (checks · findings · gates · cost), the
  **dead-man banner**, next expected run, links. Renders with JS disabled.
- **`/runs`** — monthly-paginated index; a `quiet` badge is a first-class, non-apologetic state.
- **`/runs/<id>`** — the record rendered: checks grouped by family (passes collapsed but present,
  each with its `curl` line), findings with sources and evidence paths, the absence-of-evidence
  block, actions/gates/decisions/refusals, the cost breakdown to four decimals, the audit events,
  a **Verify** button (browser: re-derives findings from evidence via `src/verify` and re-checks the
  hash chain via a seeded sluice `MemoryStore` — zero server), plus raw-JSON and git-blob links.
- **`/checks`** — the catalog: every rule id, what it asserts, what evidence it records, what its
  finding looks like. Rendered from the same registry the runner uses, so docs cannot drift.
- **`/gates`** — open gates (from the committed file, tokenless) and the decision history.
- **`/gate`** — one static page reading `?id`/`?t` and `pending-gates.json`; the only page that POSTs.
- **`/methodology`** — the rubric (§7) in prose, the schema link, the anti-manufacture rule, the
  autonomy ladder, and **Limitations**.

**Dead-man banner (D3-safe).** The static payload carries `lastRunAt` + `nextExpectedAt`; the banner
is **client-side arithmetic** — no function, no network. > 36h late: "This watch may have stopped —
last run was N days ago." `<noscript>` prints both timestamps. A stale site never presents itself as
current, and a paused Vercel project cannot make the banner lie.

## 11. Eval / golden set ($0, CI stage 5)

**CI: `typecheck → lint → unit → e2e:smoke → eval`.** Deterministic product ⇒ **zero-tolerance bar**;
a percentage would be dishonest.

1. **Schema + rubric over all history** — `dogwatch verify --all --rerun-rules` on every committed
   record on every push. Findings re-derived from stored evidence must match byte-for-byte.
2. **Planted violations** — `fixtures/violations/` holds one record per rubric rule (15+): an
   unsourced finding, an empty-findings record with an empty checks array, a silently-skipped check,
   a finding whose statement was hand-edited, a metric promoted to a finding, a cost with no usage,
   an advisory citing a nonexistent finding id, a broken chain, a leaked token. **Each must fail with
   its exact code**; a violation that merely warns fails CI.
3. **Replay goldens** — four recorded probe transcripts (quiet run · findings run · gated run ·
   degraded/no-store run) replayed through the real pipeline with a frozen clock and seeded ids,
   asserting a **byte-identical** record. This is what proves the published records are reproducible.
4. **Gate-flow scenarios on sluice `MemoryStore`** — open→approve→execute (exactly one issue via
   `FakeTransport` ledger), duplicate poller (still one), crash mid-execute then resume (still one),
   reject → refusal recorded, timeout → fail closed, decision race → first writer wins, token replay
   → `E_BAD_TOKEN`.
5. **Drift checks** — `dogwatch render` output matches the committed index and pending-gates file;
   the README numbers block is regenerated and diffed; a secret-pattern scan runs over `runs/**`.
6. **e2e:smoke** — Playwright against `next build && next start`: `/` renders with JS disabled, a run
   page shows checks/findings/absence/cost, the Verify button turns green on a good record and red on
   a tampered fixture, footer + favicon present.
